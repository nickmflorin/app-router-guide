Chapter 10 · Part C — Decouple the Parts

Minimize the Wires

Every prop, callback, and context read is a wire — a dependency connecting two parts of the UI. Wires are not free: each one couples a component's future to its neighbors'. This chapter is about keeping components independent, and why repetition beats plumbing.

10.1 The cost of a wire

When a parent fetches data and passes it down, the parent stops being a layout concern and becomes a data router. It must know what every descendant needs, fetch the union of it, and thread it through — and from that moment, three components change together forever. Child B needs one more field? You edit Child B, the parent's fetch, and the prop signature in between. Multiply by every feature for the life of the product and the parent becomes what we'll call a coupling layer: a component whose main job is re-wiring everyone else's requirements.

The rule that falls out of this is blunt: never pass a child anything the parent does not itself need. React Critical If the parent isn't using the data — isn't branching on it, isn't laying it out — the parent is just a wire, and wires should be deleted. Legitimate exceptions: identity (an id the child will use to ask its own questions), composition (children and other slots), and configuration the parent genuinely owns (a variant, a size).

10.2 Repetition over dependency

The instinct that produces drilling is a good one — don't fetch the same thing twice. For most of React's history, the only way to honor it was to fetch once at the top and share downward. Hooks and context were the first crack in that constraint; in Next, deduped fetches and cached functions remove it entirely. It is better for two components to ask the same question independently than to be wired together — because the framework guarantees the question is only answered once per request. app/programs/[id]/page.tsxexport default async function Page({ params }) {
  const { id } = await params;
  // The only wire is identity.
  return (
    <>

}
components/program/ProgramHeader.tsxexport async function ProgramHeader({ programId }) {
  /* It asks for itself — the dedupe layer
     makes this free (§11). */
  const program = await getProgram(programId);
  return <header>{program.name} …</header>;
}

Both ProgramHeader and ProgramStats call getProgram(id); only one real request happens, because the data layer is deduped (§11 covers the mechanics — cache(), fetch dedupe, SWR keys). The page went from a data router back to what it should be: structure. And each child is now portable — drop it into any page, any parallel route, any dialog, hand it an id, and it works.

This works on both sides of the boundary

Server-side, independence is free via React.cache() and fetch dedupe. Client-side, the same pattern holds with useSWR/React Query: two components calling useProgram(id) share one cache entry and one request. What you should not do is hand-roll it — a fetch in an effect has no dedupe layer, so drilling becomes "necessary" again. The anti-patterns feed each other.

10.3 Independence changes how the page streams

Wiring isn't just a maintenance cost — it determines where your Suspense boundaries can go. A boundary must sit above whatever awaits. If the parent fetches and drills, the boundary is forced above the parent: the whole subtree is one all-or-nothing unit, gated by its slowest request. If children fetch for themselves, each child gets its own boundary inside the parent — the structure renders instantly and each region streams in as its answer arrives.

10.4 Callbacks up are wires too

Passing data down is half the coupling story; the other half is children reporting back up. A callback prop that exists so a child can tell its parent "something changed, please refetch/re-render" is a wire pointing the other direction — and it usually means the coordination is happening at the wrong layer. Communicate through shared infrastructure instead of through parents: React Critical

  • The URL — filters, tabs, selection, pagination. A filter bar that calls router.replace() with new search params doesn't need to know a table exists; the table re-renders because the page's inputs changed (§6).
  • Cache invalidation — after a mutation, revalidatePath/revalidateTag on the server, or SWR/React Query invalidation on the client. Every component reading that data updates, with no parent orchestrating (§11).

Legitimate exceptions: genuinely local, ephemeral coordination — a form field telling its form it changed, a listbox item telling its listbox it's highlighted. The test is whether the two components form one composite widget with one responsibility, or whether a callback is smuggling app-level data flow through the component tree.
